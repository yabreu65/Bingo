# M5.7 — Certificación del cliente TV

> **M6 T6:** LOCAL_TV permanece bloqueado en builds de producción hasta su certificación. No hay fallback automático a SERVER; la TV muestra un aviso y no solicita medios. El procedimiento siguiente conserva valor para desarrollo y futura certificación. Ver `m6-t6-boundaries.md`.

## Resultado de compatibilidad

La arquitectura `REMOTE_PRESENTIAL + LOCAL_TV` es viable **con condiciones**:

- La aplicación debe servirse por HTTPS en el evento.
- El servicio local debe escuchar únicamente en `127.0.0.1`.
- El encargado debe aprobar el permiso `loopback-network`/red local cuando el navegador lo solicite.
- El servicio debe iniciarse con `--allow-origin` igual al origen HTTPS exacto del evento para que la comprobación `/health` sea legible mediante CORS.
- El navegador puede bloquear autoplay; la TV muestra un botón de reproducción manual.
- Si la verificación falla, no se cambia automáticamente a `SERVER`, evitando distribuir multimedia comercial por el servidor público.

Referencias de plataforma:

- https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Local_network_access
- https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Mixed_content
- https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay

La compatibilidad real del dominio HTTPS, navegador y versión del sistema operativo queda clasificada como `REQUIERE PRUEBA REAL`.

## Procedimiento para la laptop de Margarita

1. Conectar la laptop a la TV y verificar que tenga la biblioteca autorizada, sin copiarla al repositorio ni al servidor central.
2. Generar el manifiesto local:

   ```bash
   node tools/generate-local-tv-manifest.mjs \
     --root /ruta/privada/biblioteca \
     --out /ruta/privada/tv-media-manifest.json
   ```

3. Iniciar el servicio:

   ```bash
   node tools/local-tv-media-server.mjs \
     --root /ruta/privada/biblioteca \
     --manifest /ruta/privada/tv-media-manifest.json \
     --port 8787 \
     --allow-origin https://DOMINIO-REAL-DEL-EVENTO
   ```

4. Confirmar localmente `http://127.0.0.1:8787/health`.
5. Desde el organizador, generar el enlace temporal de TV y abrirlo en la laptop conectada a la TV.
6. Aprobar el permiso de red local/loopback si aparece.
7. Confirmar en la pantalla TV:
   - `servicio local disponible` o `reproducción local activa`.
   - reproducción de audio/video sintético.
   - ausencia de errores de permiso o servicio.
8. Probar un karaoke y un reto musical.
9. Detener el proceso con `Ctrl+C` al terminar.

## Diagnósticos visibles

- Servicio local verificando/disponible/no disponible.
- Permiso de red local denegado.
- Autoplay bloqueado con botón `Reproducir música` o `Reproducir karaoke`.
- Archivo multimedia ausente.
- Estado resumido de medios TV visible para el organizador.

Los eventos `tv-media-status` solo transportan estados operativos. No incluyen tokens, credenciales, rutas absolutas ni secretos.

## GO / NO-GO

### GO

- Dominio HTTPS real cargado en la laptop.
- Permiso loopback aprobado o no requerido.
- `/health` responde y el navegador puede leerlo o el recurso multimedia confirma acceso.
- MP4/MP3 sintético reproduce y avanza `currentTime`.
- Socket.IO/WSS continúa conectado.
- TV recupera el reto activo después de reconexión.
- No existen solicitudes centrales de medios en `LOCAL_TV`.

### NO-GO

- El navegador deniega loopback o bloquea el contenido mixto.
- El servicio escucha fuera de `127.0.0.1`.
- El servicio local no puede verificar el manifiesto.
- La reproducción falla y el encargado no puede iniciar manualmente.
- El flujo requiere desactivar CSP, Permissions-Policy, autoplay o protecciones globales.
- Se pretende abrir un túnel o distribuir archivos comerciales para compensar el bloqueo.

## Pruebas que permanecen pendientes

- Página HTTPS pública real con el dominio definitivo.
- Prompt real de Local Network Access en el navegador elegido.
- Reproducción desde la red y hardware de Margarita.
- Medición real de reconexión WSS durante una interrupción de Internet.
