# M5.2 — Multimedia policy by device

M5.2 connects the room modality metadata to the existing React clients without changing the game engine or Socket.IO contracts.

## Effective policy

| Mode | TV surface | Player surface | External sources |
|---|---|---|---|
| `LEGACY` without an explicit policy | Enabled | Existing behavior preserved | Enabled |
| `LOCAL` | Enabled by default | Optional by default | Disabled by default |
| `REMOTE_PRESENTIAL` | Enabled by default | Optional by default | Disabled by default |
| `DISTRIBUTED` | Both by default | Optional by default | Disabled by default |

Explicit room policy fields override these defaults independently.

## Field semantics

- `primarySurface: tv` allows TV media and does not grant any socket or organizer permission.
- `primarySurface: players` allows player media and leaves TV media unmounted.
- `primarySurface: both` allows both surfaces.
- `playerPlayback: disabled` does not mount the player media component on player screens.
- `playerPlayback: optional` keeps the player available but requires an explicit player opt-in before synchronized playback starts on non-legacy guest screens.
- `playerPlayback: required` allows synchronized playback to start subject to normal browser autoplay rules.
- `allowExternalSources: false` prevents Deezer players from mounting. Challenges remain answerable and display a non-blocking status.
- `allowExternalSources: true` permits the existing Deezer preview flow; it does not grant authorization or bypass Socket.IO rules.

## Compatibility

- A room without `eventMode` or `multimediaPolicy` resolves to `LEGACY` and keeps the previous behavior.
- Room configuration is refreshed from the public room endpoint during session restoration, so reconnecting clients receive current modality policy without exposing capabilities.
- `optional` is not equivalent to `disabled`: the component remains available, but playback is consent-driven for distributed guest clients.
- Missing local media never blocks challenge completion; the existing fallback and authoritative server timers remain in control.

## Client boundaries

- `PlayerCardView` and `WaitingRoom` gate the synchronized player component.
- `ChallengeModal` gates local karaoke and external Deezer previews while preserving answers and timers.
- `TVDisplay` gates the main video, TV challenge media and effects audio.
- No policy value is used as an organizer or TV credential.
