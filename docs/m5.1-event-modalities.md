# M5.1 — Event modality compatibility

M5.1 adds metadata for event modality without changing the game engine, Socket.IO handlers, or current media playback.

## Modes

| Value | Meaning | Selectable for new rooms |
|---|---|---:|
| `LEGACY` | Existing room with no explicit modality | No |
| `LOCAL` | Organizer, TV, and players share a local event network | Yes |
| `REMOTE_PRESENTIAL` | Organizer/server is remote while TV and players meet in one venue | Yes |
| `DISTRIBUTED` | Players connect from different locations | Yes |

## Compatibility rules

- A room without `config.eventMode` resolves to `LEGACY` in memory.
- A legacy room without `config.multimediaPolicy` keeps the previous playback behavior.
- Creating a new room without an explicit mode normalizes it to `LOCAL`.
- New rooms default to `playerPlayback: optional`; React clients do not consume this policy yet.
- `LEGACY` is accepted by the model as an internal compatibility value but rejected by the REST create/update schemas.
- Updating an unrelated setting on a legacy room does not add modality fields.
- Selecting a mode for a legacy room is the explicit point at which its modality metadata is introduced.

## Scope boundary

This change does not implement remote TV authorization, public HTTPS/WSS configuration, multimedia routing, or new UI controls. Those belong to M5.2–M5.4.
