# M5.4 Public Access Architecture

## Decision

Use one public HTTPS origin (architecture A) in the event profile. The frontend reverse proxy exposes `/api` and `/socket.io` to the private Node process. MongoDB and the backend port remain private. This keeps browser API, Socket.IO, QR codes, and temporary TV links on the same origin.

The explicit backend profiles are `BINGO_ACCESS_MODE=local`, `lan`, and `public`. The repository defaults to `local`; switching to `lan` or `public` is an operator action and is not automatic.

## Configuration

Backend variables:

- `BINGO_ACCESS_MODE`: `local`, `lan`, or `public`.
- `FRONTEND_URL`: canonical browser origin.
- `ALLOWED_ORIGINS`: comma-separated exact origins; never `*`.
- `LAN_ORIGINS`: exact LAN origins used only by `lan` mode.
- `TRUST_PROXY_HOPS`: `0` locally, `1` when behind the single nginx/tunnel proxy.
- `MONGODB_URI`: private MongoDB URI; never publish its port.

Frontend variables:

- `VITE_BACKEND_URL=http://localhost:5001` for direct local development.
- `VITE_BACKEND_URL=same-origin` for the nginx/reverse-proxy profile.
- `VITE_NETWORK_IP` only when a LAN QR must be generated while the browser is opened on localhost.
- `VITE_SHAREABLE_ORIGIN` for an explicitly configured public or LAN origin.

Production builds now enforce same-origin API/Socket.IO regardless of a stale development `VITE_BACKEND_URL`. Public mode rejects every non-HTTPS allowlisted origin, and proxy hops must be an integer. `/api/live` is process liveness; `/api/health` and `/api/ready` are database-aware readiness (503 until usable). See `m6-t6-boundaries.md` for index/topology requirements and remaining infrastructure checks.

## Local and LAN operation

1. Keep `BINGO_ACCESS_MODE=local` for localhost-only development.
2. For a LAN event, set `BINGO_ACCESS_MODE=lan`, `FRONTEND_URL` to the Mac's LAN origin, and list every browser origin in `LAN_ORIGINS`.
3. Build or run the frontend with the explicit LAN origin. Do not rely on a hardcoded private IP.
4. Keep MongoDB bound to localhost/private infrastructure and expose only the frontend port to the LAN.
5. Stop the backend, frontend and MongoDB test process after the event.

## Public HTTPS operation (not activated by M5.4)

Run nginx and the Node backend on the same private host. Publish only nginx through a named HTTPS tunnel. The nginx config forwards API requests and WebSocket upgrades to `backend:5001`; the compose file no longer publishes the backend port.

Before starting a real event, set `BINGO_ACCESS_MODE=public`, use an HTTPS `FRONTEND_URL`, set `ALLOWED_ORIGINS` to that exact origin, set `TRUST_PROXY_HOPS=1`, and configure `VITE_BACKEND_URL=same-origin`. The tunnel must route only to nginx, not to MongoDB or Node directly.

Cloudflare documents full WebSocket support for Tunnel and recommends keepalives; the app already uses Socket.IO reconnection and heartbeat behavior. Cloudflare Quick Tunnels are temporary, have changing hostnames, no uptime guarantee, and a documented limit of 200 in-flight requests, so they are suitable for development validation, not a production event. Named public applications require a Cloudflare account and a domain on Cloudflare. These statements were checked against the official documentation on 2026-10-29:

- https://developers.cloudflare.com/tunnel/get-started/
- https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/
- https://developers.cloudflare.com/cloudflare-one/faq/cloudflare-tunnels-faq/
- https://developers.cloudflare.com/network/websockets/

No tunnel was opened while implementing M5.4.

## Temporary Bingo QR entry overlay (not deployed)

`ops/private-staging/compose.contabo-trial-public-entry.yaml` is a Bingo-only Traefik label overlay. It is not a replacement for shared Traefik configuration. The committed `compose-public-entry.fixture.yaml` is test-only and must never be used to deploy. No Contabo deployment or live Traefik test has been performed.

### Route policy

| Public surface | Method and path | Guard that remains |
|---|---|---|
| Entry UI and assets | `GET`/`HEAD` `/`, `/player/<6-char-code>`, `/tv/<6-char-code>`, `/assets/`, `/music/`, `/sounds/`, `/vite.svg` | Bare `/` redirects to protected `/organizer`; valid legacy `?room=`/`?tv=` links are translated in the frontend. |
| Player REST | `POST /api/rooms/join`; `GET /api/rooms/<code>`; `POST /api/rooms/<code>/select-card` and `/reconnect`; `GET /api/players/<24-hex-id>` | Admission rules and player capabilities still apply to sensitive reads/writes. |
| TV REST | `POST /api/rooms/<code>/tv-authorization/claim` and `/renew` | One-time link/session authorization remains separate from host and player capabilities. |
| Socket.IO | `GET`/`POST /socket.io` and `/socket.io/` | Event-level player/host/TV checks remain. Traefik is configured for average `50` requests/second and burst `150`; live source-IP and WebSocket behavior is unverified. |

The organizer path `/organizer`, room creation, configuration, administration, and TV link issue/revoke paths remain on the lower-priority Basic Auth fallback. The backend and MongoDB stay private with no public Traefik route or host-published port. Query parameters do not select Traefik routers; they are retained only for safe legacy-link translation and TV token handoff.

## Media

The frontend serves local `/music` and `/sounds` assets and nginx preserves HTTP byte ranges. The repository intentionally excludes the real multimedia library from Git. A future event operator must mount or provision the authorized library into the frontend runtime without committing it. The 70/70 local media audit remains the source of truth; CI uses only its versioned fixtures.

Phones configured with M5.2 playback disabled do not mount MP4 elements. TV and centralized playback remain the primary media surface for `LOCAL` and `REMOTE_PRESENTIAL`.

## Security checklist

- Exact CORS origins; no wildcard.
- Socket.IO checks the same origin policy and limits payloads to 100 KB.
- Socket event bursts are bounded per connection.
- `TRUST_PROXY_HOPS` is explicit and never inferred from client headers.
- Request/error logs redact tokens, capabilities and authorization query parameters.
- Temporary TV links remain hash-only in MongoDB and retain M5.3 expiry/revocation semantics.
- MongoDB and the backend port are not published by the production compose profile.
- HTTPS, domain ownership, Cloudflare account configuration, bandwidth suitability, and rights to distribute local media require event-specific verification.
