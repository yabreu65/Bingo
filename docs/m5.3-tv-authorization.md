# M5.3 — Temporary remote TV authorization

M5.3 adds a TV-only authorization path for remote event rooms. It does not replace the existing popup handoff used by LEGACY and LOCAL rooms.

## Security model

1. The organizer authenticates REST requests with the existing `x-room-host-capability` (or the existing authenticated host/admin path).
2. `POST /api/rooms/:code/tv-authorization` creates a cryptographically random one-time link token.
3. MongoDB stores only the room-bound SHA-256 hash and a short link expiration. The raw token is returned once to the organizer so it can be copied to the remote TV.
4. `POST /api/rooms/:code/tv-authorization/claim` atomically consumes the link and issues a separate TV session token.
5. The TV session token is kept in the TV tab's `sessionStorage`, never in the URL after claim, and is sent in `x-tv-session-token` for renewal.
6. `POST /api/rooms/:code/tv-authorization/renew` renews only a live, unrevoked session.
7. `POST /api/rooms/:code/tv-authorization/revoke` invalidates the link/session and disconnects the temporary TV socket.

The link TTL is configured by `TV_AUTH_LINK_TTL_SECONDS` (default 10 minutes, bounded to 1–15 minutes). The session TTL is configured by `TV_AUTH_SESSION_TTL_SECONDS` (default 24 hours, bounded to 5 minutes–7 days).

## Socket.IO contract

- Legacy/local popup clients continue to join with `tvCapability` and are marked `tvAuthorizationType: legacy`.
- Remote clients join with `playerId: tv-display` and `tvSessionToken`; the server validates the room-bound hash and expiry before binding the socket.
- Only one temporary TV socket is active per room in the current Socket.IO process. A disconnected TV can reconnect with the same valid session.
- Temporary TV sockets cannot claim player identities or organizer capabilities. Existing server-side checks remain authoritative for karaoke completion, trivia control, tie-breaks, and game controls.
- Revocation, room closure, and game finalization disconnect temporary TV sockets.

## Public data boundary

`tvAuthorization`, capability hashes, and all raw capabilities are excluded from public room responses. Tokens are not logged by the authorization routes or socket join flow.

## Client behavior

- Remote organizer rooms show a Premium Festivo control to generate, copy, inspect, and revoke a temporary TV link.
- The TV claims the link over HTTPS, removes `tvToken` from the browser URL, renews the session, and reconnects through Socket.IO.
- Expired or revoked links show a clear TV error and do not fall back to organizer credentials.
