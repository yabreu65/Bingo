# M6.2 temporary-staging release package

**Scope:** source package and review plan only. This is not deployment authorization and is not a production release. No Contabo connection, Docker runtime, MongoDB service, image pull, dependency install, or staging action is part of preparation.

## Release contents and identity

`ops/private-staging/m6.2-package-inputs.json` is the reviewed selection policy. It fixes base branch `main`, HEAD `020d654276d2b6b4a98b886a37deebe2ae51bc72`, target `linux/amd64`, and the SHA-256 of the filtered tracked path snapshot. It selects the tracked backend/frontend files at that exact source base plus an explicit list of M6 source, tests, private-staging operations, and review documentation. The generated `MANIFEST.json` records every actual archive path, source class, Git status, normalized mode, byte size, and SHA-256. The worktree bytes—not HEAD alone—are the released source.

The tracked input set contains 229 files. All `.env*` files (including `.env.example`) are excluded; their contents were not opened for this package. `bingo-react/public/music/**` is excluded even though commercial media is present locally and ignored by Git. The tracked `bingo-react/public/sounds/` assets remain eligible. `ops/private-staging/m6.2-package-inputs.json` enumerates the additional M6 files; the generated manifest is the authoritative exact full path list.

The generator derives a release ID from the fixed source HEAD, target platform, locked image references, path snapshot, and all selected file hashes. It creates a deterministic gzip/USTAR archive (normalized mode, owner and mtime) and verifies the member set and content hashes before writing. The outer archive SHA-256 and manifest SHA-256 are recorded in the external `SHA256SUMS` sidecar. These checksums are created with the artifact and must not be copied into this source document, which is itself part of the archive.

## Included and excluded classes

Included:

- Backend and frontend tracked source/build inputs and package lockfiles, except denied paths below.
- Explicit untracked M5/M6 implementation and acceptance tests listed in the input policy.
- Private-staging Compose, Mongo bootstrap, ingress configuration, static validation runner and tests.
- M6 operational and review documentation, including this procedure and the refreshed publication manifest.
- Image-lock and package-builder sources. The package contains no image layers or installed npm dependencies.

Explicitly excluded:

- Every `.env*` file, secret, Mongo keyfile, credential, backup, private key, or generated certificate.
- `backend/.tmp-*`, WiredTiger/database files (`*.wt`, `*.bson`, `WiredTiger*`, journal/diagnostic data), T7/T8 local metric/diagnostic JSON, and `docs/m6-t8-inventory.json`.
- `bingo-react/public/music/**` (commercial music and local karaoke media), `.DS_Store`, logs, uploads, `node_modules`, `dist`, coverage, and other build/runtime output.
- `odd/**`, internal task/patch artifacts, rehearsal/development Compose, unrelated root documentation, and local media-server tools.

The builder reads only the allowlist. It rejects staged changes, a different branch/HEAD/path snapshot, missing or symlinked inputs, excluded paths, excessive size, digest drift, and high-confidence secret patterns. It never archives the repository root or relies on `.gitignore` alone. Its secret-pattern scan is a high-confidence heuristic, not a complete secret scanner; the prior history audit is separate evidence and is not repeated here.

## Build and transfer procedure

The authorized local artifact directory is `/private/tmp/bingo-m6.2-release-020d654`. The builder creates it only if absent, with restrictive permissions; if it already exists, the build fails without overwriting it. The directory is outside Git and is not part of the repository.

```sh
python3 ops/private-staging/build-m6.2-package.py
```

The command is deterministic for identical allowlisted bytes and policy. It writes `MANIFEST.json`, `<release-id>.tar.gz`, and `SHA256SUMS` to that exact directory. Preserve all three together. Do not rename or alter them after checksumming.

For a future owner-authorized transfer, use an approved secure channel. On the destination, first verify `sha256sum -c SHA256SUMS`, inspect the manifest and archive member list, then extract only into a new release-specific directory. Never transfer `.env` files, credentials, keyfiles, local database directories, metric artifacts, or commercial media. This procedure was not executed against a VPS.

## Ownership and retirement

Create a deployment-time ownership record before startup containing the exact release ID, Compose project, container IDs/services, image IDs/digests, networks, named volumes, extraction directory, secret paths, access route, any Tailscale-managed certificate reference, uploaded/synthetic data, and owner. Expected Compose volume names are `bingo-private-staging_mongo-data`, `bingo-private-staging_mongo-config-data`, `bingo-private-staging_uploads`, and `bingo-private-staging_backend-logs`; expected networks are the project-scoped `database`, `application`, and `ingress` networks. Verify actual names and labels at deployment time; do not infer ownership from a name alone.

**A. Reversible stop:** after separate authorization, use the project-scoped Compose `stop`. A project-scoped `down` may remove only that project's containers/networks while preserving named volumes. Keep the archive, manifest, config, credentials, and volume inventory for restart/review. Do not pass `-v` or `--remove-orphans`.

**B. Definitive removal:** requires a later, separate owner authorization after the retention/backup decision. Verify project/owner labels and exact IDs, stop Bingo, then remove only the four verified Bingo-owned volumes and the approved release/secret/log directories. Remove only locally built images proven exclusive to this project; do not remove shared/preloaded Mongo, Node, Nginx, or Traefik images. Remove only the Bingo-specific access mapping; never run a global Tailscale Serve reset or delete shared certificates. Do not use `docker system prune`, volume prune, wildcard deletion, or any cleanup that can affect PawTech/other projects. No deletion command is authorized or executed by M6.2.
